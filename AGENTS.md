## Repo notes

- **Tool registry.** Adding a tool takes all three edits: the component in `components/tools/MyTool.tsx` typed `React.FC<ToolComponentProps>`, an import in `App.tsx`, and an entry in the `TOOLS` array in `App.tsx` holding `id`, `name`/`nameZh`, `description`/`descriptionZh`, `category`, an icon from `components/Icons.tsx`, `keywords`, and `component: <MyTool lang="en" />`. Miss the array entry and the tool never reaches the sidebar. That `component` value is a placeholder element: `App.tsx` re-renders it through `React.cloneElement`, injecting the live `lang`, `state`, `onStateChange`, and `onNavigateToTool`. `ToolDef.component` is typed `ReactElement<ToolComponentProps>`, so a component that cannot receive `lang` fails the typecheck.
- **Ids address state, but only for tools that opt in.** `App.tsx` keeps one blob per tool id in `toolStates`, written back by whichever tool is mounted and read through its `state` prop. Only tools that accept `state`/`onStateChange` keep their work across navigation — currently `JsonFormatter`, `YamlTool`, `TextProcessor`, `MortgageCalculator` and `FormatConverter`; know which side of that line a new tool belongs on before claiming its input survives. Most converters do not persist at all, which is the default to assume.
- **i18n is an inline ternary**, with no library: a component builds a local `t` object from `lang === 'zh' ? … : …`. Every user-visible string needs both languages, as do `nameZh` and `descriptionZh`.
- **Hand-offs travel as props.** `onNavigateToTool(targetId, payload)` switches tools and shallow-merges `payload` into the target's persisted state, which the target reads from its `state` prop. `JsonFormatter`, `YamlTool`, `TextProcessor` and `FormatConverter` are wired this way; route new hand-offs through the same pair. When the target *parses* what it receives, the payload also carries `sourceFormat` and is a one-shot signal: `FormatConverter` lets it outrank the format it remembered itself, while leaving the target format the user last chose alone. Send raw text, valid or not — the receiver owns the error message.
- **Shared tool helpers live in `components/tools/shared/`.** `useCopy` (clipboard + copied flag), `CopyButton` (the one copy affordance: icon/label swap, `text` may be a `() => string` getter for text that is expensive to build), `pill` (active/idle tab classes), `hex` (`toHex`/`fromHex`/`textToHex`/`hexToText`), `highlight` (`escapeHtml`, `MAX_HIGHLIGHT_SIZE`, and `highlightLang` for whole-document highlighting that falls back to escaped text when a grammar is missing — highlight.js ships none for CSV) and `CodeEditor` (textarea over a highlighted `<pre>`, configured by an `EditorShell`). Add a copy button or a byte↔hex conversion there instead of re-writing one per tool.
- **The format converter's core is a pure module** (`shared/convert.ts`): `convert(input, from, to, options)` parses into a JS value and serializes out of it, so N formats cost 2N paths instead of N² — and the pivot never travels through JSON text, because that would strip class-based values (TOML's dates) and silently change their type. It holds no user-facing prose: every message is a `MessageKey`, and `Record<MessageKey, …>` in the component means a new key fails the typecheck until it is worded in both languages. `shownOutput` and `readInitialState` live there too so they can be tested without React. A new format means extending `FORMATS` and the read/write branches. One pair is impossible by construction — CSV always reads into an array of rows, and a TOML document root must be a table — so `isPairSupported` disables that combination in the pills (and repairs an old stored blob that holds it) rather than letting the user pick a pair that can only fail. Shape-dependent failures stay errors, since parsing is what decides them. CSV uses `papaparse` strictly as a tokenizer; the mapping decisions (headers, column names, types, ragged rows) are ours.
- **App state is partly durable.** Language, theme and sidebar collapse persist in `localStorage` under `nbt.*`; the open tool is mirrored into the URL fragment (`#json-fmt`), so a tool can be linked to and survives a reload. Unknown fragments fall back to home.
- **Tailwind arrives by CDN**, not as a dependency: the `tailwindcss.com` script tag in `index.html`, with no `tailwind.config.js`. Add theme tokens and the `darkMode: 'class'` switch to the inline `tailwind.config` block there, which already carries `primary-500/600` and `slate-750` (the defaults need no restating), beside the styles in its `<style>` block — the opt-in `.no-scrollbar` class that the sidebar nav uses, since the repo has no stylesheet file.
- **Four libraries are consumed as page globals**, loaded from tags in `index.html`: `Diff` (jsdiff), `QRCode`, `jsonpath`, `hljs`. Each consuming file declares the one it uses — `declare const Diff: any;` in `TextDiff.tsx`.
- **The Gemini key is substituted at build time.** `services/geminiService.ts` reads `process.env.API_KEY`, which Vite's `define` fills from `GEMINI_API_KEY` in `.env` (copy `.env.example`). Every function it exports returns `Promise<string | null>`, where `null` means "no result" (missing key, an unusable request, or a failed call); the service holds no user-facing prose, so each caller renders its own localized failure.
- **Verify with `bun run verify`** (typecheck → build → test → smoke; the individual scripts stay available), all clean on `main`. `vite build` bundles through esbuild without typechecking. Unit tests are `*.test.ts` files sitting beside the module they cover, run by Bun's own runner via `bun test`; `scripts/smoke.tsx` is a headless render of `App` asserting the tool grid and deep links — it is no longer the only test-shaped file. `@types/bun` supplies the `bun:test` types and is listed in `tsconfig.json`'s `types`. Note that `tsconfig.json` does not enable `strict`, so `tsc` will not catch a `null` whose caller treats it as a string.
- **Bun owns the lockfile** (`bun.lock`): `bun install`, `bun run dev` (port 3000), `bun run build`.
- **`migrated_prompt_history/` is an archive** of past session transcripts that no code references. Scope searches away from it: `rg -g '!migrated_prompt_history' …`.
